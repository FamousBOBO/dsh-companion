## 1. 起点：base 上 15 项失败，其中 13 项在媒体页

（另外 2 项是 `设置：tab 数量异常` 与 `聊天：缺少 layout 服务时没有可读提示`，属 W1 之前的既有问题，与本轮媒体页无关。）

G0 记录的是「媒体页 fixture 与页面期望漂移」。实测后发现这个描述**不够准**：13 项里既有 fixture 漂移，也有页面真缺功能，还有 1 项真实无障碍缺陷。逐项定性如下：

| # | 失败项 | 真实原因 | 处置 |
|---|---|---|---|
| 1 | 缺少 provider「Index-TTS」 | provider 名来自 descriptor，页面**只渲染被选中的那一个**，其余 4 个 tts provider 从不出现 | 页面改成渲染**全部** provider 卡（`section.providers.map`） |
| 2 | 已选 OpenAI-compatible 没有自动展开 | 断言用中文标签 `Base URL` 找输入框，而 descriptor 给的 label 是「服务地址」 | 断言改成按**控件 id**（`media-<path>`）定位 |
| 3 | 找不到识图开关 | `locked` 分区默认 `open=false`，且 locked 时开关被替换成一个「未启用」Badge | locked 分区也渲染开关（强制 `disabled`），并默认展开 |
| 4 | 识图分区没有说明「预留，当前关闭」 | descriptor 的 `section.note` **从来没被渲染过** | 分区头渲染 `section.note` |
| 5 | 找不到 Index-TTS 卡 | 同 #1 | 同 #1 |
| 6 | 找不到 NAI 卡 | 同 #1 | 同 #1 |
| 7 | OpenAI 卡里没有 API Key 输入 | 同 #2（label 是「密钥」，不是「API Key」） | 同 #2 |
| 8 | 找不到「协议」选择器 | 协议用 `ui.Segmented`（一组 `<button>`）渲染，**没有 `<select>`、也没有 id** | 改用真 `ui.Select` + id，外面套 `ui.Field` |
| 9 | P2 有草稿时没有提供「放弃未保存的改动」 | 按钮文案是「放弃修改」 | 文案对齐为「放弃未保存的改动」 |
| 10 | **P3「协议」select 没有 id** | **真实无障碍缺陷**：label 的 `for` 落不到控件上 | 同 #8（顺带修掉） |
| 11 | 找不到「预览」按钮 | descriptor 有 `preview` 描述，页面**从未渲染**任何预览入口 | 新增预览块，按 `preview.endpoint` 发一次 GET |
| 12 | 无法把「启用生图」重新打开 | 上一轮切协议时页面把 `enabled` 置 false 但草稿状态卡住 | 随 #8 的协议重写修复（保存流程重新走通） |
| 13 | 清除后找不到保存按钮 | provider 保存按钮文案是「保存」而非「保存这个 provider」 | 改名，与"这一块"的保存区分开 |

**结论：13 项里只有 2 项（#1/#5/#6 同一根因）算 fixture 漂移，其余 10 项是页面真的缺东西或真的写错。** 这一点写清楚了，因为把 10 项都当成"测试过期"去改测试，等于把缺陷留在产品里。

## 2. 顺带修掉的三个真实缺陷（不在原 13 项里）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| `cpxp-media-cards` 类名被 `classOf(...).includes('cpxp-media-card')` 命中 | 整段 provider 列表被当成**一张卡**，`cardByText` 永远只能拿到第一个 provider | 包装类改名 `cpxp-media-provider-list` |
| 生成字段（步数/种子/采样器）不在 `provider.fields`，`providerDirty` 也不看它们 | 「改了步数却按不动保存」 | dirty 判据纳入 `generationFields` |
| NAI 的生成编辑器只有「被选中的 provider」才渲染 | 切到 NAI 前根本看不到步数 | 每个带 `generationFields` 的 provider 各自渲染编辑器 |

## 3. 七条可断言的规则（`scripts/check-visual-a11y.mjs`）

计划 W5 的四条要求不做成"看着还行"，而是变成可执行的判据。`npm run check:a11y`（`--strict` 有问题即退出 1）：

| 规则 | 判据 | 为什么这么定 |
|---|---|---|
| `hardcoded-color` | CSS 里出现与主题无关的十六进制色 | 换主题必漏；但 `var(--token, #fallback)` 里的兜底值与 token 声明行**不算**（那是出处） |
| `mouse-only-handler` | `div/span/tr…` 带 `onClick` 却无键盘处理 | 键盘用户完全按不动；`aria-hidden`/`backdrop` 的装饰层除外（Esc 才是它们的键盘路径） |
| `bare-outline-none` | `outline:none` 且同块内无替代焦点样式 | 焦点框消失 = 键盘用户丢失位置 |
| `fixed-width-without-max` | ≥240px 固定宽度却无 `max-width` | 窄窗口横向溢出 |
| `missing-focus-visible` | 只写 `:focus` 且涉及 outline | 鼠标点击也画焦点框是噪声，但用 `:focus-visible` 才对 |

**首轮跑出 43 项真问题**，逐项修完（不是改规则迁就现状）：

- 26 处写死颜色 → 全部换成 `var(--cpx-console-*, #fallback)` / `var(--dsw-alias-*, #fallback)` 等 token，覆盖 `pages-operator.js`（终端配色 13 处）、`keyword-map.js`（连线配色 5 处）、`pages-chat-settings.js`、`core.js`、我自己 W1/W2 新增的两个片段；
- 1 处真正的键盘缺陷 → `Table` 的可点行加 `tabIndex/role/aria-label/onKeyDown`（Enter/Space）；
- 两条规则本身写错、修的是规则：`aria-hidden` 的正则少了引号容错；装饰性遮罩不该按可聚焦控件算。

**最终：`✓ 七条规则全部通过`，`--strict` 退出 0。**

### 3.1 规则本身也有测试（14 个用例）

`test/visual-a11y.test.mjs` 用**合成片段**验每条判据的正反两面（14 条用例，含 4 个历史盲区的对照），避免"规则写错了却全绿"：写死色 vs token 兜底 vs token 声明；键盘处理缺失 vs 有；装饰遮罩；`outline:none` vs 有替代；宽固定宽度 vs 有 `max-width`；`:focus` vs `:focus-visible`。另有一条断言 W1–W3 新增的三个片段**真的**被扫描且真的声明了样式。

## 3.2 导航表的所有权收回到一处

`pages-health.js` 原来在加载时**改写** `P.NAV`（给「生活与日程」补 `tabs`）。这违反计划里"单文件所有者"的一条：导航表由 `core.js` 定义，别的片段不该在运行时改它——否则"13 个入口"这件事永远没有单一事实来源。

- `core.js` 自己声明 `life: tabs: ['life','health']`；
- `pages-health.js` 改成**只读自检**：声明缺了就往控制台报一条 `warn`，不再悄悄补上（悄悄补的后果是"下次声明再丢掉也没人知道"）；
- `core.js` 里 "The seven first-level entries" 的注释同步成现状（13 个），并说明每个条目都是本插件的注册页。
## 4. 窄窗口与减少动画

先诚实记一笔：本节初稿写「`pages-works.js` 自带 760px 断点」，实测**当时是 0 个 `@media`**——写了但没核。核对后补了断点，下面是补完的实测计数：

| 片段 | `@media` | `prefers-reduced-motion` | 具体做了什么 |
|---|---|---|---|
| `pages-trace.js` | 2 | 1 | 760px 以下五列栅格（76+62+88+auto ≈ 266px）改成两行堆叠：时间与阶段并排、正文独占一行；列表 `max-height` 从 52vh → 60vh |
| `pages-works.js` | 2 | 1 | 760px 以下列表项从「标题 + 侧栏」并排改成上下堆叠；预览区 `max-height` 46vh → 38vh |
| `settings-search.js` | 2 | 1 | 面板宽度 `min(760px,100%)`；760px 以下改顶部对齐；脉冲高亮在减少动画下改成静态描边 |
| `pages-media.js` | 3 | 1 | 新块（provider 列表 / 预览区 / 启用行 / `fieldset`）补 `min-width:0` 与 760px 断点，避免新加的东西自己成为溢出源 |

`core.js` 的 `@media (prefers-reduced-motion: reduce)` 覆盖 `.cpx-app *`（含新片段的动画），四个新片段各自另有局部规则。

**这仍然只是声明的断点，不是实测的布局结果**——见 §7。
