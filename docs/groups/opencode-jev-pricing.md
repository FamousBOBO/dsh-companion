# opencode 上的 Jev：免费版 vs 付费版

> 类型：report
> 日期：2026-11-20
> 作用域：`opencode.ai` 的 `systemone` 端点（`jev-1.13` / `jev-1.13-free`）；对照本机 `jev-local`
> 证据级别：real-api（真实调用、真实计费字段、真实 429）
> 状态：现行

## 一句话

**免费版和付费版是同一个模型**（`canonical_id: typesafe/jev-1.13.0`）——
判决逐条一致（9/9 同向、平均概率差 0.0033）、延迟同一档（p50 851 vs 882 ms）、
能力完全一致（`noul`/`choice`/`score` 都通、20 问一次也行）。
差别在额度：**免费版每天只有约 58K input token**（≈77 轮群聊判断），用完就 429，
次日 UTC 00:05 重置。

代价对比也很清楚：付费版按 **$0.042/1M input tokens**（output 免费）计费，
群聊真实一轮（11 问、两条十来字的消息）**752 token ≈ $0.00003**——
**一天全速判断 1728 轮也只有 $0.055；普通群（每 5 分钟）一个群一个月 $0.27。**

还有一条容易被误判的：**那 752 token 里只有 67 是群消息本身（9 %）**，
259 是 Jev 自己的固定模板（34 %），426 是九个问句的正文（57 %）。
消息再长也涨不动——**涨的是问句数，每个问句约 +31 tok**。

## 1. 两个 id，同一个模型

`GET https://opencode.ai/inference/v1/models` 里两条记录的 `canonical_id` **完全相同**：

| id | canonical_id | type | input 价 | output 价 | context |
|---|---|---|---|---|---|
| `jev-1.13` | `typesafe/jev-1.13.0` | `decision` | $0.042 / 1M | 0 | 64 000 |
| `jev-1.13-free` | `typesafe/jev-1.13.0` | `decision` | 0 | 0 | 64 000 |

同一个 state（"订单晚了三天还坏了，我要退款"）两边的答案：

| 问句 | `jev-1.13` | `jev-1.13-free` |
|---|---|---|
| 这是退款请求吗（noul） | 0.98 | 0.98 |
| 要求他现在处理吗（noul） | 0.60 | 0.62 |
| 哪个团队（choice） | `returns` 0.99 | `returns` 0.99 |

三轮 state × 三个问句的一致性抽测（9 个判决）：

| 项 | 值 |
|---|---|
| 判决方向不一致 | **0/9** |
| 概率最大差 | 0.01 |
| 概率平均差 | 0.0033 |

**免费版不是"小一号的模型"，是同一个模型的促销入口。** 所以"免费的和付费的有什么区别"
这个问题的答案不是"质量"，只有"额度"。

## 2. 延迟：同一档（差异在网络，不在模型）

每个 config 各跑 30 次，state 在三条夹具之间轮换（避免服务端复用同一份 prefix）：

| 配置 | p50 | p90 | min | max | 均值 |
|---|---|---|---|---|---|
| 付费 · 1 问 | 851 ms | 1863 | 656 | 2285 | 1046 |
| 免费 · 1 问 | 859 ms | 1210 | 639 | 1502 | 909 |
| 付费 · 9 问 | 857 ms | 1654 | 613 | 2386 | 1059 |
| 免费 · 9 问 | 882 ms | 1078 | 602 | 2004 | 948 |

四组的 p50 都落在 **850–880 ms**，与"问几句"无关（九门一次问完不会更慢）。
免费那两组均值反而低一点，但 p90 抖动更大——那是网络，不是模型。

> 注意量级：本机 `jev-local` 是 **301 ms**。opencode 这条路多出来的 ~550 ms
> 全部是**网络往返**（本机到 opencode 的真实网络下限，之前测同一服务 `GET /v1/models`
> 就花了 1.1 秒）。所以"本地 vs 托管"的差距不是 2 倍，是 3 倍。

### 2.1 用量字段（这是唯一能拿到成本证据的地方）

同一次请求的 `usage`：

```jsonc
// jev-1.13
{ "input_tokens": 379, "output_tokens": 71, "cost": 0.00001592,
  "opencode": { "billing_source": "balance", "list_cost": 0.00001592,
                "tokens": { "input": 379, "output": 71, "reasoning": 0,
                            "cache_read": 0, "cache_write_5m": 0, "cache_write_1h": 0 } } }

// jev-1.13-free
{ "input_tokens": 379, "output_tokens": 71, "cost": 0,
  "opencode": { "billing_source": "free", "list_cost": 0, "tokens": { … } } }
```

两条都报 `output_tokens: 71`（每个问句 ~20 token 的判决载荷），但**只按 input 计费**。
`billing_source` 是 `balance` / `free` 二值——**这就是"这次算不算钱"的唯一判据**，
比看 `cost` 更可靠（`cost` 在免费版恒为 0，看不出"本该多少钱"）。

## 3. 免费版的额度：约 **58K input tokens**（不是一个请求数）

连打 120 次免费模型（间隔 50 ms）：

| 结果 | 次数 |
|---|---|
| `200` | **13** |
| `429 FreeUsageLimitError` | 107 |

第 **14** 次就开始 429，错误体原文：

```json
{"type":"error","error":{"type":"FreeUsageLimitError",
 "message":"Free usage limit reached. Free models work in OpenCode (https://opencode.ai);
  subscribe to OpenCode Go to keep going: https://opencode.ai/go"}}
```

### 3.1 用实测 token 反推额度

`429` 的响应头里带 `Retry-After`，把它与本地时钟相加能钉出重置时刻：

```
01:15:03 发出 → Retry-After 24610 s → 重置于 2026-11-20 08:05:13（本机）
01:15:24 发出 → Retry-After 24589 s → 重置于 2026-11-20 08:05:13   ← 同一秒
01:15:45 发出 → Retry-After 24568 s → 重置于 2026-11-20 08:05:13   ← 同一秒
```

**UTC 00:05 是固定的每日重置时刻**（本机 UTC+8 → 08:05）。不是"发出后 N 小时"。

所以额度是**每日 input token 配额**。把这轮会话里所有免费成功请求的
`usage.input_tokens` 加总（87 % 是服务端回执，13 % 按同类实测值补）：

| 分组 | 每次 input | 次数 | 小计 |
|---|---|---|---|
| 首次单测（订单 state · 3 问） | 379 | 1 | 379 |
| bench12 · 1 问 | 391 | 12 | 4 692 |
| bench12 · 9 问 | 614 | 12 | 7 368 |
| bench30 · 1 问 | 391 | 30 | 11 730 |
| bench30 · 9 问 | 614 | 30 | 18 420 |
| 并发 20（2 行 state · 1 问） | ~330 | 20 | 6 600 |
| 大状态 50 行 · 1 问 | 2 964 | 1 | 2 964 |
| 一致性抽测（2 问含 choice） | ~461 | 1 | 461 |
| freecap · noul | 311 | 1 | 311 |
| freecap · score | ~315 | 1 | 315 |
| freecap · 20 问 | 623 | 1 | 623 |
| 额度探针成功的那 13 次 | 311 | 13 | 4 043 |
| **合计** | | **123 次** | **57 906** |

撞墙那一次需要 311 tok 才能通过，所以上限落在
**[57 906, 58 217) ≈ 58K**。

这就是为什么"第 14 次就 429"看起来像次数限制：那 13 次探针每次 311 tok，
前面几轮 benchmark 已经吃掉 53.5K，剩余空间只够 13 次小请求。
**按次数记永远算不准，必须按 token 算。**（前几版文档按"125 次"记，是被这个假象带偏的。）

### 3.2 一轮真正要多少 token

先别估算，把它拆成三块量出来（同一模型、同一会话、4 次付费请求，合计 $0.00004）：

| 组成 | 实测 | 说明 |
|---|---|---|
| **固定模板** | **259 tok** | Jev 自己的系统提示与问句骨架，每次请求必付一次，与内容无关 |
| **每条群消息** | ~1 tok / 字 | 15 字的一条消息 ≈ 15 tok |
| **每个问句框架** | **11 tok** | 问句的 `type` / `instructions` 字段结构 |
| **问句正文** | ~1 tok / 字 | 九门问句平均 20.2 字 → 182 tok |

用这三块拼出真实形状（state = 两条十来字的消息、67 字符）：

| 形状 | 推算 | **实测** | 误差 |
|---|---|---|---|
| 只问九门（9 问） | 607 | **567** | +40 |
| 九门 + 短语库 4 选项（10 问） | 699 | **690** | +9 |
| 九门 + 短语 + 目标（11 问） | 743 | **752** | −9 |

**这一轮 = 752 input tok ≈ $0.0000316。** 拆开看：

| 部分 | tok | 占比 |
|---|---|---|
| 固定模板（Jev 的，不是你的） | 259 | **34 %** |
| 问句正文（九门 + 短语 + 目标标题） | ~426 | **57 %** |
| 群消息本身 | 67 | **9 %** |

你的直觉是对的：**群消息那几十个字只占 9 %。** 钱主要花在"每轮都要把九个问句的正文重发一遍"
和 Jev 那 259 token 的固定模板上。所以消息再长也不怎么涨——**涨的是问句数**，
每多一个问句约 +31 tok（11 框架 + 20 字正文）。

### 3.3 58K 能撑多久（用实测 752 tok/轮）

| 节奏 | 每日轮数 | 免费 58K 够跑 |
|---|---|---|
| 每 50 秒（`judgeIntervalMs` 下限） | 1728 | **77 轮 = 1.1 小时** |
| 每分钟 | 1440 | 77 轮 = 1.3 小时 |
| 每 5 分钟 | 288 | 77 轮 = **6.4 小时** |

三种都撑不满 24 小时。**等价付费金额只有 $0.0024**——免费额度值两厘钱。

## 4. 能力：完全一致（都在 `systemone` 端点）

| 项 | 两边 |
|---|---|
| 问句类型 | `noul` / `choice` / `score` 全通 |
| 一次多问 | 20 问一次 → 200，全部返回 |
| 64K 上下文 | 50 行状态（2964 input token）→ 200 |
| `temperature` / `top_p` | **不支持**（传了就 400 `api_usage_error`） |
| `chat/completions` | **不支持**（400 `ModelProtocolUnsupported`） |
| `messages`（Anthropic 协议） | **不支持**（同上） |
| 图片输入 | 模型声明支持（`image/png`、`image/jpeg`），未测 |

最后两条最要紧：**Jev 只能走 `systemone` 端点**，它不是聊天模型。
把 `jev-1.13` 加成 DSH 的普通 provider（走 `openai-completions` 或 `anthropic-messages`）
会在第一次调用时拿到 `ModelProtocolUnsupported`。要在 DSH 里用它，得走
`judge.backend` 那条（P10 已经实现了本地版；托管版要另写一个 `JudgePort` 适配器）。

## 5. 钱：把实测单价折成群聊场景

单价 $0.042 / 1M input tokens（output 免费）。实测 input（state = 两条十来字的消息）：

| 场景 | input tokens | 单次成本 |
|---|---|---|
| 只问九门（9 问） | 567 | $0.0000238 |
| 九门 + 短语库 4 选项（10 问） | 690 | $0.0000290 |
| **九门 + 短语 + 目标（11 问，本机真实形状）** | **752** | **$0.0000316** |

按判断频率折成月成本（**每群**）：

| 频率 | 轮/天 | tok/天 | 付费/月 | 免费（58K）够跑 |
|---|---|---|---|---|
| 每 50 秒（`judgeIntervalMs` 下限） | 1728 | 1.30 M | **$1.64** | 77 轮 = **1.1 小时** |
| 每分钟（忙群） | 1440 | 1.08 M | $1.36 | 77 轮 = 1.3 小时 |
| 每 5 分钟（普通群） | 288 | 0.22 M | **$0.27** | 77 轮 = 6.4 小时 |

**结论：免费版撑不住群聊。** 一个普通群一天要 288 轮判断，免费那 58K 只够 77 轮
（四分之一天）；而付费版一个月 $0.27——**这个量级上"省这两毛七"不值得换一个每天会断的路径**。

对照本机 `jev-local`：**零费用、301 ms、不依赖网络**。托管这条路唯一的优势是
**不用装 495 MB 权重、不占 693 MB 显存**。

## 6. 该怎么选

| 你的情况 | 选 |
|---|---|
| 群聊一直在跑（判断频繁） | **本机 `jev-local`**（P10）：零费用、301 ms、无额度 |
| 机器显存/内存紧张，装不下 693 MB | 托管 `jev-1.13` 付费（$0.27–1.64/月/群） |
| 只是试一下 Jev 判得准不准 | 托管 `jev-1.13-free`（够跑几十次实验） |
| 想接进 DSH 当普通模型 | **做不到**：Jev 只走 `systemone`，不是 chat 模型 |

## 7. 复现

脚本在 `E:\llm-eval\`（不进仓库）：

| 脚本 | 干什么 |
|---|---|
| `jev_opencode_bench.py` | 付费 vs 免费 × 1 问 / 9 问 × 30 次，含一致性抽测 |
| `jev_quota_probe.py` | 连续 120 次找免费额度断点 |
| `jev_free_state.py` | 额度用完后再打 3 次（验证不恢复） |
| `jev_freecap.py` | 免费版的问句类型 / 20 问 / 大状态上限 |
| `jev_as_chat.py` | 验证 `chat/completions` 与 `messages` 都不支持 |
| `jev_cost_math.py` | 把单价折成月成本与"免费额度能撑多久" |

两个踩过的坑：

1. **Python `urllib` 的默认 UA 会被 Cloudflare 拦成 `403 error code 1010`**——
   必须显式带一个自己的 UA（`dsh-jev-bench/1.0`）；
2. `OPENCODE_GO_API_KEY` 那把 key **不能**调 `systemone`（`401 Invalid credential`）；
   `jev` 只在 `OPENCODE_API_KEY`（Console/PAYG）上可用。

## 8. 没测的

- **付费版的限频**：按要求没测（会烧钱）。只知道连打 30 次没有 429。
- **图片输入**：模型声明支持，没测。
- **免费额度的重置时刻**：从 `Retry-After` 反解出 UTC 00:05（三次采样落在同一秒），`Retry-After` 本身在 6.8 小时内缓慢递减；没验证跨日后额度是否整额恢复（那要先等一天）。
- **`gpt-6-luna-decision` / `gemini-decision-1`**：同端点、同协议，没测（贵 2.4–2.4 倍）。
