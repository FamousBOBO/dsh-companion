# 本地 Jev 与托管 Jev 在真实私聊上的对照

> 类型：report
> 日期：2026-11-20
> 作用域：`jev-local`（本机 0.8B Q4_K_M + Vulkan）vs `jev-1.13`（opencode 付费托管）
> 证据级别：real-api + real-corpus（1040 条真实 QQ 私聊原话，两边喂同一份 state）
> 状态：现行

## 一句话

**同一个语料、同一份 state、同一组九门问句，两边都问完 100 轮**：
托管版在 46 轮判"该回"，本机在 0 轮判"该回"——
**净效果一致只有 44/100**。

但这不是"本机更差"。原因是这份语料是 **QQ 私聊**（只有一个发送者、中位 5 个字），
而本机的决策表第 3 条是"两个人你一句我一句 → 别插进去"。
`one_to_one` 门在这份语料上本机只判 true 2/100、托管判 48/100 ——
**托管那个 48 才是错的**（私聊本来就一对一，它不该是常态）。

---

## 1. 方法与对齐

| 项 | 做法 |
|---|---|
| 语料 | `E:\llm-eval\dm-lines.json`：1040 条去重后的真实 QQ 私聊消息（2026-10-30 → 11-14） |
| 一轮 | 连续 6 条消息（1 条滑动），共 1034 轮；这次跑前 100 轮 |
| 输入 | **两边喂完全同一串 `renderJudgeState` 输出**（本地 dump 出来，托管照原样发） |
| 问句 | 九门问句逐字取自 `judge-gates.ts`，两边一致 |
| 阈值 | `p(true) ≥ 0.5` 即判 true（托管返回的 `noul` 就是 p(true)，本地按同一公式算） |
| 决策表 | 同一张 `ruleTable`（Python 侧逐条同序抄，避免口径漂移） |

**为什么必须喂同一份 state**：第一版我两边各自拼 state，结果 `tech_issue` 一致率只有 98/100
却出现"仅托管 2、仅本地 0"的怪现象——那是输入漂移，不是模型差异。对齐之后才可信。

## 2. 逐门一致率（100 轮）

| 门 | 一致 | 同 true | 仅本地 true | 仅托管 true |
|---|---|---|---|---|
| `tech_issue` | 98/100 | 0 | 0 | 2 |
| `help_open` | **51/100** | 0 | 1 | **48** |
| `one_to_one` | **92/100** | 1 | 1 | **7** |
| `conflict` | 98/100 | 0 | 0 | 2 |
| `privacy` | **100/100** | 0 | 0 | 0 |
| `inject` | 99/100 | 0 | 0 | 1 |
| `closed` | 88/100 | 1 | 0 | 12 |
| `casual` | **75/100** | 0 | 0 | **25** |
| `share` | 84/100 | 1 | 4 | 11 |

三个安全门（`conflict` / `privacy` / `inject`）两边几乎全一致，
**分歧全在"该不该开口"那几门上**——而且方向一致地偏向"托管更愿意说话"。

## 3. 那 46 轮托管说要回，本机一句没说

托管判 `reply` 的 46 轮，最后一条真实消息：

```
#  1  '在干啥呢'
#  2  '恩 快了吧'
#  3  '哎呀 不管了 抱抱'
#  4  '还是宝宝好'
#  5  '想看胸了'
#  6  '嗯嘛 宝宝求求你啦 宝宝最好了'
# 12  '恩？想要一起吗'
# 24  '女生有 cd 吗'
```

其中**只有 12/46 含疑问词**。也就是说托管判"有人提了问题还没人答"（`help_open`）时，
把"在干啥呢""还是宝宝好""想看胸了"都算了进去。

本机在**同样这 46 轮里 46 次全判 silent**（45 次 `no-topic`、1 次 `private-pair`）。

### 3.1 谁对？

这条得分开看，不能一句话结案：

- **`help_open` 那 48 次"仅托管 true"** → **本机对**。`help_open` 问的是"有人提了问题
  而且还没人回答他"，而"还是宝宝好""想看胸了"不是问题。托管把亲昵句当成了求助。
- **`casual` 那 25 次"仅托管 true"** → **托管对**。"午安呢""在干啥呢""一不注意又干到半夜"
  确实是日常闲聊，本机判 false 是漏了。
- **`one_to_one` 那 7 次"仅托管 true"** → **托管对**（私聊就是一对一），
  但本机判 false 反而是"在这个场景下不该 true"——这条门在私聊里没有意义。

所以净效果 44/100 这个数字**不能读成"本机判错了 56 次"**。它读成：
**两个模型的"该说话"阈值差得很远**，而这份语料（亲昵私聊、几乎全是闲聊）倾向托管那一侧。

## 4. 逐门余量：本机很"敢"判 false，托管很"敢"判 true

`p(true)` 中位数（0.5 是分界）：

| 门 | 本地 p(true) p50 | 托管对应倾向 |
|---|---|---|
| `tech_issue` | 0.116 | 两边都低 |
| `help_open` | 0.208 | 托管常 > 0.5 |
| `one_to_one` | 0.342 | 托管常 > 0.5 |
| `conflict` | 0.140 | 两边都低 |
| `privacy` | **0.049** | 两边都极低（最稳的一门） |
| `inject` | 0.127 | 两边都低 |
| `closed` | 0.148 | 托管偶尔 > 0.5 |
| `casual` | 0.185 | 托管常 > 0.5 |
| `share` | 0.212 | 托管偶尔 > 0.5 |

本机九门的 `p(true)` 中位数**全部低于 0.35**——它对"这里有事发生"这件事系统性偏保守。
这不是缺点（群聊里多说话的代价比少说话高），但它解释了为什么真实私聊上它 94% 不说话。

## 6. 结论该怎么用

| 问题 | 答案 |
|---|---|
| 两个模型判断力差多少？ | **在"安全"上没差**（3 个安全门 98–100% 一致）；差在"愿不愿意开口" |
| 本机是不是更差？ | 不。`help_open` 那 48 次托管误判亲昵句为求助，**那批本机是对的** |
| 本机是不是漏判？ | 是。`casual` 漏 25 次（闲聊它判 false），这是 0.8B 的系统性保守 |
| 能直接换吗？ | **不能**。这份语料上净效果只有 44/100，换过去群聊会明显变安静 |
| 那要怎么办？ | 见下 |

### 6.1 要换就得先做两件事

1. **重标一份"短语库形状"的语料**——现有 52 条 `judge-jev.mjs` 语料是按生成式期望写的
   （`expect` 是"回一句具体的话"），本机只能从 13 条短语里选，那份语料上注定低分。
   真实私聊这份又太偏"亲昵闲聊"，两个都测不出判断力；
2. **本机在群聊语料上重跑**——私聊里 `one_to_one` 本来就不该 true，这项指标必须换到
   真实群聊上才有意义。本机日志里有 1433 条 `presence` 记录，但**只记结论不记正文**
   （"判断为不说话（speak-false:…）"），拿不到可重放的群消息原文，所以这次只能退到私聊。

## 7. 复现

| 脚本 | 干什么 |
|---|---|
| `plugins/dsh-channel-qq/eval/group/llm/judge-jev-real.mjs` | 真实语料 → 本机判断；`--dump` 落盘每轮的门与 verdict |
| `E:\llm-eval\_dm_lines.py` | 从 `data\tmp\qq-dm-*.jsonl` 抽真实消息行（去重 1040 条） |
| `E:\llm-eval\jev_hosted_vs_local.py` | 托管侧跑同一批 state，落 `jev-vs-rounds.json` |
| `E:\llm-eval\_cmp.py` | 逐门一致率、动作分布、净效果一致率 |

跑法：

```powershell
$env:JEV_SCORE_BIN='E:\llm-eval\jev-src\jev-score.exe'
$env:JEV_MODEL='E:\llm-eval\jev-model\Jev-Style-0.8B-Decision-v3-Q4_K_M.gguf'
$env:JEV_TOKENIZER_DIR='E:\llm-eval\jev-model\tokenizer'
node eval/group/llm/judge-jev-real.mjs --limit 100 --dump E:\llm-eval\jev-local-rounds.json
E:\llm-eval\venv-jev\Scripts\python.exe E:\llm-eval\jev_hosted_vs_local.py --rounds 100
```

**语料不进仓库**（`eval/group/llm/dm-lines.local.json` 已在 `.gitignore` 里，含用户原话）。

## 8. 没测的

- **真实群聊**：拿不到可重放的群消息正文（日志只留判断结论）。这是这份对照最大的局限。
- **超过 100 轮**：只跑了前 100 轮（托管侧花钱，$0.0035）。全量 1034 轮约 $0.036。
- **短语文案质量**：两边文案不可比（本机 13 条固定短语，托管返回的是概率不是文本）。
- **`jev-1.13-free`**：免费额度每天只有 58K token，跑不完 100 轮（见 `opencode-jev-pricing.md`）。
